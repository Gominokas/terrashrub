概要

tesh（terrshrub）は、単一コードベースで複数環境・複数クラウド・オンプレを管理するインフラ構成管理ツール。Terraformやk8sマニフェストの上に位置し、「共通ベース + 代替パーツ + 差分 + 変数可視化」で複雑さを制御する。

コアコンセプト

land — 正規のベースインフラ定義。k8sベースで書く。全環境に共通するデフォルト構成。何も差し替えなければlandがそのまま適用される。

shrub — landとは独立した代替モジュール群。landの一部を差し替えたいときにshrubから呼び出す。例：landのAPインスタンスをスペック違いに差し替える、landのIngressをCloudflare Workersに差し替える。

vars — 変数定義レイヤー。landとshrub内の変数プレースホルダ §@変数名§ に対応する値を定義する。クラウド別・環境別の値セットを持つ。

envdiff — 環境ごとの差分定義。3つの役割を持つ：landから弾くモジュールのリスト、shrubから取るモジュールのリスト、varsのどの値セットを使うかの指定。

ディレクトリ構成

tesh/
├── land/                  # ベースインフラ定義
│   ├── `ap.tf`
│   ├── `db.tf`
│   ├── `network.tf`
│   └── `ingress.tf`
├── shrub/                 # 代替モジュール
│   ├── `ap-small.tf`
│   ├── `ap-large.tf`
│   ├── `cloudflare-workers.tf`
│   └── `aws-lambda.tf`
├── vars/                  # 変数定義
│   ├── common.vars        # 全環境共通
│   ├── aws.vars           # AWS固有
│   ├── cloudflare.vars    # Cloudflare固有
│   ├── staging.vars       # staging固有
│   └── production.vars    # production固有
├── envdiff/               # 環境差分
│   ├── dev.diff
│   ├── staging.diff
│   └── production.diff
└── tesh.config.json       # tesh設定

envdiff の定義フォーマット

envdiff/staging.diff
exclude\_from\_land:

- `ap.tf`

include\_from\_shrub:

- `ap-small.tf`

vars:

- common.vars
- aws.vars
- staging.vars

変数の仕組み

landとshrub内に変数プレースホルダを埋め込む。

land/ap.tf
resource "kubernetes\_deployment" "ap" \{
replicas = §@ap\_replicas§
image    = §@ap\_image§
\}

vars で値を定義する。

vars/staging.vars
@ap\_replicas=2
@ap\_image=myapp:staging-latest

CLI コマンド

tesh checkout  — デバッグ用プレビュー。land + shrub + envdiff + varsを合成し、変数を §値@変数名§ 形式で展開して出力。terraform実行はしない。

出力例
replicas = §2@ap\_replicas§
image    = §myapp:staging-latest@ap\_image§

値と変数名が両方見えるので、解決結果が正しいか目視確認できる。

tesh plan  — land + envdiff + vars を合成し、変数を値のみに展開した純粋なTerraform定義を生成、terraform plan を実行する。

tesh apply  — tesh plan と同様に合成・展開し、terraform apply を実行する。

tesh diff   — 2環境の合成結果を比較し、差分を出力する。引っ越しやクラウド切り替え時の確認用。

tesh validate — 全環境のenvdiffを検証。未定義変数、存在しないモジュール参照、循環参照をチェック。

変数解決の優先順位

varsに複数ファイルが指定された場合、後に書いたものが優先。

vars:

- common.vars # 最低優先
- aws.vars # 上書き
- staging.vars # 最高優先

同じ @ap\_replicas が common.vars と staging.vars の両方にあれば、staging.vars の値が使われる。

合成フロー

1. envdiff を読み込む
2. land から exclude\_from\_land に該当するファイルを除外
3. shrub から include\_from\_shrub に該当するファイルを追加
4. 2と3を合成
5. vars を優先順位に従って解決
6. 合成結果内の §@変数名§ を値に置換
7. checkout → §値@変数名§ で出力
plan/apply → 値のみで出力し terraform 実行

tesh.config.json

\{
"version": "1.0",
"project": "my-infra",
"land\_dir": "./land",
"shrub\_dir": "./shrub",
"vars\_dir": "./vars",
"envdiff\_dir": "./envdiff",
"terraform": \{
"backend": "s3",
"state\_prefix": "tesh"
\},
"output\_dir": "./.tesh\_build"
\}

Statics Lead との連携

static3d deploy が tesh を呼び出す。static3d.config.json に tesh のパスを指定。

\{
"infrastructure": \{
"engine": "tesh",
"config": "./infra/tesh.config.json",
"environment": "production"
\}
\}

static3d deploy 実行時に、アプリのビルド・デプロイと同時に tesh apply でインフラも構築・更新される。
